## 2024-05-18 - Expandable Accordion Accessibility
**Learning:** Using an `onClick` on a non-interactive `div` for expandable sections (accordions) creates keyboard accessibility issues, as users cannot tab to the header and press Enter/Space to expand it. In `Experience.tsx`, a `div` wrapped the header content with a nested `button` for the icon, which was semantically incorrect and un-navigable.
**Action:** When implementing expandable UI patterns like accordions, use a full-width `<button>` for the entire clickable header area. Ensure you remove any nested interactive elements (like a secondary button inside it) and correctly apply `aria-expanded` and `aria-controls` to the main button to provide clear screen reader support and natural keyboard navigation.

## 2024-05-19 - Conditional Rendering and ARIA Controls
**Learning:** In React apps, conditionally rendering a panel based on state creates accessibility issues for screen readers if the toggle button doesn't explicitly declare an `aria-controls` attribute linking to an `id` on the conditional panel. Also, missing `aria-expanded` attributes on "Show More" style buttons (like in `Credentials.tsx`) leaves screen reader users uninformed about the state of the content they are toggling.
**Action:** Always include both `aria-expanded={booleanState}` and `aria-controls="panel-id"` on disclosure buttons. When conditionally rendering the panel, ensure the wrapper element has the matching `id="panel-id"` so the screen reader can associate the control with the newly appearing content.
