## 2024-05-18 - Expandable Accordion Accessibility
**Learning:** Using an `onClick` on a non-interactive `div` for expandable sections (accordions) creates keyboard accessibility issues, as users cannot tab to the header and press Enter/Space to expand it. In `Experience.tsx`, a `div` wrapped the header content with a nested `button` for the icon, which was semantically incorrect and un-navigable.
**Action:** When implementing expandable UI patterns like accordions, use a full-width `<button>` for the entire clickable header area. Ensure you remove any nested interactive elements (like a secondary button inside it) and correctly apply `aria-expanded` and `aria-controls` to the main button to provide clear screen reader support and natural keyboard navigation.
## 2024-05-18 - Missing ARIA Attributes in Expandable Sections
**Learning:** Found an accessibility issue pattern across this app's components regarding expandable sections (e.g. accordion or show/hide patterns). Specifically in `Projects.tsx` and `Credentials.tsx`, the `button` elements used to toggle additional content are missing the `aria-controls` attribute, and sometimes the `aria-expanded` attribute. Furthermore, the targeted content wrappers lack proper `id`s to associate them with the controls.
**Action:** When adding or reviewing toggle buttons that expand/collapse content, always ensure the presence of both `aria-expanded` (with boolean state) and `aria-controls` referencing the unique `id` of the content block. Added `aria-live="polite"` as well to dynamic content loads, especially those revealing a grid of items.
